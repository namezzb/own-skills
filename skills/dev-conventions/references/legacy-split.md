# 老逻辑不动 + 按区分条件分流

## 原则

需求开发时，**原始的老逻辑一行都不要改**。新功能必须通过「区分条件」（如新加的 `protectType` / `mode` / 版本号 / 来源字段等）进行分流：

- 入口处按区分条件 if-else / switch 分流到新方法 vs 老方法
- 新方法可以参照、复制老方法的写法，但独立实现（允许局部重复代码）
- 禁止"顺手优化"老方法、"顺手修复"老 bug、"顺手重构"老结构
- 禁止在老方法内部加 if 分支夹带新逻辑（老方法的行为必须保持二进制等价）

## Why

老逻辑跑了多年、被线上验证过、被现有测试覆盖。任何修改都可能引入回归。新需求通过分流隔离到新方法，只有新分支需要验证，老分支零风险。

## How

- 校验、转换、SQL、路由等任何"按条件做不同事"的场景，先看入口能不能加一个判断把新老彻底分开
- 如果新老需要共享部分代码，**提取共用 helper** 而不是修改老方法
- 实在无法分流的边界情况（如新加字段导致 SQL 结构不得不改），只做**结构必需**的最小修改，不做任何风格调整

## 示例结构

```java
// 入口处分流，老逻辑完全不动
if (isNewMode(request)) {
    return processNewLogic(request);
} else {
    return processOldLogic(request); // 老方法，原封不动
}
```
